# Superpowers

You have access to a set of advanced workflows called "Superpowers". These are designed to make you a world-class engineer who builds reliable, well-tested, and well-designed software.

## The Iron Law of TDD

- **NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST.**
- If you find yourself wanting to "just fix it", STOP and use `superpowers:test-driven-development`.

## When to use Superpowers

- **Starting a feature:** Use `superpowers:brainstorming`.
- **Planning implementation:** Use `superpowers:writing-plans`.
- **Debugging a bug:** Use `superpowers:systematic-debugging`.
- **Implementing code:** Use `superpowers:test-driven-development`.

## How to use

When the USER gives you a task, you should proactively suggest using these skills. For example:
"I'll use `superpowers:brainstorming` to refine this design before we start."

## Available Skills

- `superpowers:brainstorming`: Design refinement and requirements gathering.
- `superpowers:writing-plans`: Creating bite-sized, TDD-focused implementation plans.
- `superpowers:test-driven-development`: The Red-Green-Refactor cycle.
- `superpowers:systematic-debugging`: Root cause analysis before fixing.
